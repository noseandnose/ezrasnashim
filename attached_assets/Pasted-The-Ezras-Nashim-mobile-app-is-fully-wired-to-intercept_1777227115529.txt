The Ezras Nashim mobile app is fully wired to intercept https://ezrasnashim.app/c/*, /challenge/*, and /reset-password* as Universal Links (iOS) and App Links (Android). The mobile side is complete — but iOS and Android won't intercept those URLs until this web server publishes two .well-known files.

Please add these two files and serve them at the exact paths and content-types below. No redirects, no auth, must be HTTPS, must respond with Content-Type: application/json.

File 1: https://ezrasnashim.app/.well-known/apple-app-site-association
The URL must NOT have a .json extension. Contents:

{
  "applinks": {
    "details": [
      {
        "appIDs": ["R2W4PB95MA.com.mycompany.ezrasnashim"],
        "components": [
          { "/": "/c/*" },
          { "/": "/challenge/*" },
          { "/": "/reset-password" },
          { "/": "/reset-password/*" }
        ]
      }
    ]
  }
}

Implementation guidance
Whatever framework this project uses (Next.js / Express / Vercel static / Netlify / S3+CloudFront), the pattern is the same:

Next.js: drop the files in public/.well-known/. If Content-Type ends up as text/html, add a headers() rule in next.config.js for source: '/.well-known/:path*' setting Content-Type: application/json.
Express / Node server: add two routes that res.setHeader('Content-Type', 'application/json') and res.sendFile(...).
Vercel / Netlify static: drop in public/.well-known/ — usually just works. Verify with curl -I after deploy.
CDN-fronted static: make sure the CDN doesn't strip or mis-set Content-Type. Override at the edge if needed.
Verify after deploy
curl -I https://ezrasnashim.app/.well-known/apple-app-site-association
curl -I https://ezrasnashim.app/.well-known/assetlinks.json
Both must respond HTTP/2 200 with content-type: application/json and no Location: header (no redirects).
